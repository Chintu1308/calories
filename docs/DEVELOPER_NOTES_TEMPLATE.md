# Developer Notes — Calories

Update this file after every stage. Never document unverified behavior as complete.

## Stage log template

### Stage N — [Name]
**Status:** Not started / In progress / Verified  
**Commit:** `<hash> <message>`  
**Date:** YYYY-MM-DD

#### What we built
Explain the behavior from the user's perspective.

#### Why it exists
Explain the problem this part solves.

#### Files changed
List every file and its responsibility.

#### Code walkthrough
For each significant file, explain imports, types, variables, functions, parameters, return values, control flow, validation, errors, and connections to other modules. Use line ranges or small code snippets. Make this detailed enough for a beginner to understand and modify the implementation.

#### Data flow
Trace one request from UI through API, validation, business logic, database and back.

#### Validation and security
Explain validation, identity/ownership checks, and failure behavior.

#### Tests and evidence
List exact commands and actual results. Separate automated tests from manual checks.

#### Known limitations
List gaps honestly.

#### Interview explanation
Write a concise spoken explanation to practise.

#### Likely interview questions
Provide 3–5 questions with correct answers.

#### Practice modification
Give one small change for the student to attempt independently.
